# ADR 0002：行号供给——目录在指令里 + 归档 footer 瘦身

日期：2026-09-07 · 状态：已接受（taskfold 0.26.0）

## 背景

走查式摘要需要消息级行号引用（`L<N>`），但真实摘要信封里 span 是原生消息数组：
无编号、无可数分隔符，模型**没有任何可靠依据**产出与工件行对齐的编号（消息级计数
单元是引擎事件粒度，对模型不可见）。同时摘要节点内嵌的全量预览占折叠产物 64%
（实测 7 fold：6,587 tok），其中 `[think]` 片段占预览字符 49%，且 `fold_recall`
本可随时再生全量索引——内联全量是重复建设。

## 备选方案与实验

1. **消息内联注入 `[N]`**：wire 结构安全形态已验证（text 块塞进现有内容首部，
   `serializeMessages` 零结构变化），引用 100% 准确——但破坏前缀缓存锚：分歧点从
   指令处提前到 span 起点，warm 大 span（67K tok）折叠调用 ×4.9。否决为主路径，
   保留为 fallback。
2. **指令尾部编号目录**（采纳）：span 一字不动，指令消息（span 之后、永远 fresh）
   附 fenced 逐消息目录（`N role: 摘录`，复用 renderSpanPreview 行渲染）。
- 三臂受控实验（52 条消息真实工件、预登记、全新上下文受试）：索引臂引用 100%；
  对照臂（无目录自行数数）该规模亦 100%——目录的增量价值在机制确定性与更大规模
  保险；**扰动臂（目录标签整体 +1）37/37 处引用 100% 跟目录标签走、0 处跟真实位置
  走、全程不引 L1**，证明模型严格"照抄可见编号"而非计数。成本 ~15 tok/消息，乘在
  本来就不吃缓存的指令消息上，与 span 大小弱相关。

## 决策

- 折叠指令尾部附 `Span message index`（fenced、**非 H2 引导行**——尾部第六个 H2
  会诱导模型把目录镜像进摘要，而结构校验只查首行；另加 Mirror 禁令三重防护）。
- 指令新增引用纪律：编号照抄目录（禁止自行数消息）、源码行号必须带文件名且取自
  工具结果可见编号（禁止凭记忆估计）、无锚点时引逐字片段代替行号。
- What happened/Budget 措辞同步相位化（允许 `L<N>-<M>` 聚类 bullet），消除与旧
  "merge only same-action repeats" 的自相矛盾——同编辑原子落地。
- 摘要节点 Fold archive 改**常驻 footer**：头 3 行 + 省略行（含区间与计数）+
  tail 8 行，全部切片自 renderSpanPreview 输出（结构性防漂移、真行号）；fold
  bullet 并入消息数；0.6 近空退化守卫保留（退化为单行指针）。完整索引一次
  `fold_recall({ fold })` 可再生。
- 模型可读文本（task_end 描述、系统提示段）同步改为 footer 语义，钉扎测试防
  "no elision" 承诺回归。

## 后果

- 摘要节点常驻成本：全量预览 → 头尾窗口（实测 fold 4 节点 4.4K → ~1.2K tok，
  -72%），`[think]` 噪声随原始行一并消失；行号引用获得确定性机制供给。
- 遗留观察：head=3/tail=8 窗口定向效果无独立实验（fold_recall 兜底）；目录
  fresh 成本在大 span ~1.6K tok 且与信封尺寸临界折叠有边缘交互（记录不处理）；
  100+ 消息 span 的引用稳定性建议上线后回归抽查。
